# v0.5.2 stage 2: the design, before the code (revision 4, after the three rounds)

**Status: the consensus text under the maintainer's delegation of 2026-11-08 (#216).** Codex reviewed three rounds, all `REFUTED`
([`v0.5.2-consensus/`](v0.5.2-consensus/README.md)). Its round 3 accepted the four departures from its round 2 (sizing before the code with a frozen adequacy check,
batches never interrupted, the sinusoid rule, `J` = 4) and raised six further defects. By the maintainer's tie-break, the option more conservative against a false PASS wins: **every
correction of round 3 was adopted as Codex wrote it**, in this revision, with no further round; the end-of-round review of the commits checks their implementation. Nothing here relaxes a target, and no test changes after a result. Version 3 and
earlier batteries stay unchanged; v0.5.2 is `discovery.version: 4`, with its own code paths and a compatibility proof
that version 3's bytes do not move. Development seeds and development data only, until the code is frozen.
`method_status: not_validated`.

## 1. The size of the acceptance

**What "power to the family" means:** at least 90 % probability that **every** required member of the declared family
is certified at once, under a stated reference model in which every member is correctly calibrated. It is a statement
about that reference model, not about every population inside the tolerances.

**The reference model** ([`stage2/plasmode.py`](../validation/v0.5.2/stage2/plasmode.py)). It resamples **whole curves**
of the archived records of A0 round 2, each member standardized to mean 0 and standard deviation 1, keeping the shared
curves, the several events per curve, the tails and the missingness. It is a reference distribution for the inference
machinery: separately standardized members need not describe one physically realizable light curve, a few hundred source
curves per run do not establish the population's tail, and the records are version 3's, a proxy for version 4. The
construction is checked against the schedule (every run has its scheduled curves; a record that gave nothing would stay
an unavailable curve; the sources' SHA-256 are in `plasmode-sources.json`).

**What the first runs gave** (717 components, 2,293 members):

| `T` | `q` used | Whole family, fixed `q`, 400 datasets | First evaluation: nested, 40 datasets |
|---|---|---|---|
| 6,000 | 4.559 | 0.070 | |
| 7,000 | 4.559 | 0.6725 | |
| 8,000 | 4.567 | 0.8925 | |
| 9,000 | 4.575 | 0.955 | 39 of 40 |
| 10,000 | 4.583 | 0.9975 | 37 of 40 |
| 11,000 | 4.583 | 0.9925 | |
| 12,000 | 4.583 | 0.9975 | |
| 14,000 | 4.583 | 0.9975 | |

**The first evaluation's rule was not met and stays not met.** The rule (the smallest `T` whose one-sided 95 % bound on
40 nested datasets reaches 0.90) needs 40 of 40. The nested critical values ranged from 4.46 to 4.63.

**All four nested failures are one member**, `('a08g', 'hetero', 'hetero', 'partial', 2, '2.5', 'included', 'box_odd')`,
crossing the upper variance bound ([`plasmode-diag.json`](../validation/v0.5.2/stage2/plasmode-diag.json)). One of its 524
contributing source curves has a squared pull of 71.9 (8.5 sigma), about 13.7 % of the member's second moment. **It stays
in the reference**: taking it out or weighting it down because it limits power would change the model favourably after
seeing the result. Its record is `a08/hetero/2/2.5/307` of the archived run (status OK, seven events, pull 9.33 before standardization),
with no defect found.

**The sensitivity** ([`plasmode-member.json`](../validation/v0.5.2/stage2/plasmode-member.json); 400 datasets, the rate of this member crossing the upper variance bound at `q` = 4.58, not
the family's power). Changing the curve's weight or size without restandardizing perturbs **location, scale and tail together** (doubling its weight gives the member a variance of about
1.135): at `T` = 9,000, 0.045 as recorded, 0 with its frequency halved or removed, 0.98 doubled, 0 with the pull 25 % smaller, 0.86 larger. With each perturbed reference **restandardized**, so that
only the tail's shape differs: 0.0475 as recorded, 0.0025 halved, 0 removed, 0.135 doubled, 0 smaller, 0.3625 larger; at 10,000, 0.0125, 0.005, 0, 0.1175, 0, 0.285. **The 90 % statement stays
conditional on the declared empirical reference**, which is what guideline 1 asks for; the tail of version 4 is what the adequacy check below measures.

**The evaluation that fixes `T`, a prospective amendment prompted by that result and recorded as such.** Forty datasets
cannot separate 0.90 from 0.98 (40 of 40 has probability 0.45 at 0.98). The replacement:

- **The complete procedure in every dataset:** retention before any resampling (a member below `G_min` or with an undefined
  error is not measured, and the family fails), the studentized max-t with its own 2,000 replicates, the degenerate-replicate
  rule (11 or more: not measured, the family fails), and the additional checks per family (concatenated mean and variance
  by section x statistic x noise model, never pooled across them, under the same whole-curve weights, with the order statistic 1,935 of
  their own maximum root).
- **200 datasets per size, on a new seed label,** in the fixed order 9,000, 10,000, 11,000, 12,000, stopping at the first
  size whose one-sided Clopper-Pearson lower bound at level `1 - 0.05/4` reaches 0.90 (Bonferroni over the four looks). Sizes
  are not revisited, and none of the first evaluation's runs count. Before the run, a check on one dataset requires the critical value
  of the new code to equal that of the first evaluation's code on the same seeds. If none of the four sizes passes: STOP, to the maintainer.
- About 22 CPU-h per size (397 CPU-seconds per dataset, measured on one dataset), capped at 35.

**The result: `T` = 9,000 and `G_min` = 8,550** ([`plasmode-evaluate-9000.json`](../validation/v0.5.2/stage2/plasmode-evaluate-9000.json)). At the first size in the
fixed order, 195 of the 200 datasets certified the whole family; the one-sided lower bound at level 0.9875 is 0.9374, above 0.90, so the rule stops there and 10,000, 11,000 and 12,000 were not run.
The 5 failures are all member failures: no dataset had a member not measured, a degenerate-replicate count of 11 or more, or a failed additional check. The critical values ranged from 4.476 to 4.621, and the run spent 20.48 CPU-h
(cap 35). The statement is conditional on the declared reference model and on version 3's records, as said above; the adequacy check (below) and the known-answer gate are what measure version 4.

**`T` and validity.** `T` is chosen for power, and cost is not a criterion in this choice. It is not free of validity
consequences: `G_min`, finite-sample studentization and the tails depend on it. Those are what the known-answer gate
measures at the chosen size (section 9, step 7), with its incorrect-permission bounds; a failure there blocks permission.

**`G_min` and delivery.** `G_min = 0.95 T` contributing curves. A run is scaled so that its component's least available
priced member has `T` expected contributing curves; failing `G_min` counts against the family above. A member not priced
still blocks permission where it applies. The floor selects what is run at size; it waives nothing.

**`T` and `G_min` come from this evaluation, before the code (guideline 1).** Version 4's pulls and availability can differ, so
a **frozen adequacy check** runs before the acceptance: version 4 is run on **development seeds at the whole A0 round 2 schedule** (425,400 curves; about 7 % of the
acceptance, priced in the worksheet), the reference is rebuilt from those records **keeping the schedule frozen from version 3** (the same curves per run, no rescaling
to version 4's availability), and the complete evaluation above is repeated at the chosen `T` on a new seed label, under the same bound and the same rule. So delivery of
`G_min`, per member and branch, and the tails and cluster influence of the fragile constructions are checked by the same procedure that certifies. A failure, or a run that
cannot be completed, is a **STOP and a prospective redesign**, recorded; it never changes `T`, the schedule or the reference silently. Pooled moments are reported as diagnostics,
and certify nothing. The regimes of section 4 and the selector of section 2 do not change the family.

## 2. Five or more sectors

The grid stays at 2, 3 and 4 sectors. **Rule, for the event-based tests using A0's errors only:** a sector is eligible
when it holds at least one event whose in-event span and both baseline bands reach `min_coverage` of their expected
cadences, computed from the timestamps of the quality-filtered series and the candidate's ephemeris only. Keep the 4 eligible
sectors with the most such events, ties by the larger number of cadences in those windows, then by the lower sector number.
**The chosen sector numbers are recorded before any event is measured or any A0 error is examined, and a sector is not
replaced because its statistic or error later turns out unavailable.** The operational sector count is the number of
selected sectors that actually contribute measured events; a count outside the grid is INCONCLUSIVE for those tests.
Candidate generation is unchanged (the pairing with v0.4 requires it); the rule is flux-blind conditional on the ephemeris
and the cadences, and is stated that way.

**The selector's own evaluation, frozen here.** Development constructions with 5, 8, 12 and 20 original sectors, each with
unequal noise (factors up to 3 between sectors), gaps, changing event coverage and an ephemeris fitted on all sectors. **The default is
INCONCLUSIVE:** an A0-dependent test on a target of five or more sectors stays INCONCLUSIVE unless these constructions pass the same equivalence
as the grid: simultaneous intervals of mean and variance **wholly inside the tolerances**, as a separate family with its own familywise error of
0.05, at the size the worksheet can price. If it cannot be priced, those targets stay INCONCLUSIVE and the fact goes to the maintainer at the protocol
stop, with its cost. **Supported domain:** at most 20 original sectors; above it the A0-dependent tests are INCONCLUSIVE. The largest count
among the development references is reported, with the effect on them (46 of 100 C2 stars and 16 of 22 C3 targets have at
least five files): events lost, group errors, each decisive statistic's outcome and the INCONCLUSIVE fractions.

## 3. A0 version 4: the same mask on both sides

Real events are measured on the real-mask preprocessing, as today; each pseudo-window on the preprocessing that masks the
real events and the windows of its own comb (`J = 4`, half-width one duration, the grid of E1's arm D).

**One mask-aware callable for every decisive consumer**, `preprocess(mask) -> series`. Its contract covers **every
mask-dependent operation of the production path**: sigma clipping, the quality and overlap masks, the flatten fit, any global
component refit, normalization, the alignment of the result to the original cadence index, and the treatment of the model errors;
for the flux path (`pipeline.detrend`) and for the additive path of `battery_v51_diff.a0_depth` (`additive_residuals`, aperture
and SAP differences). `odd_even` uses the box statistics (guideline 2), and `matched_*` leave the family, recorded for the future
with E2.

**The reference check** (comb against masking one window at a time) runs on a preregistered subsample of 200 curves per required
construction and covers what A0 uses. **Its tolerances, frozen now:** the per-stratum marginal error's median absolute relative
difference at most 0.02; lag correlations within 0.03 in absolute value; the final group variances in the ratio [0.96, 1.04];
availability equal in at least 99 % of curves; decisions equal in at least 99 %. A failure blocks the affected permissions. It
is a comparison with an implementation, not an independent proof that either has calibrated errors; that is what the
acceptance measures.

E2 gives the box no certificate: it enters the acceptance like everything else.

## 4. Sabotages with no effect

**No mechanism is removed in this round.** Round 1's objections are accepted: the absence of an effect at one regime does not
establish that a protection is unnecessary, and a replacement would need its own acceptance. Guideline 7's other branch is taken:
**show the regime in which each matters**, on development seeds, paired over whole curves.

| Mechanism | Sabotage | Regime | Statistic and bound protected |
|---|---|---|---|
| per-sector errors | `pool_sectors` | white noise differing by a factor of 3 between sectors, both positive group weights and signed odd/even contrasts | sd of the pull of the affected group statistic against 1.10 and 0.90 |
| dependence correction | `neff_equals_n` | long noise of correlation time 2 d, amplitude equal to the white level | sd against 1.10 |
| conditional phase-0.5 exclusion | `force_phase_half` (it forces **no** exclusion) | secondaries of 10 and 30 times the error of the phase-0.5 depth, beyond A0.8's near-threshold 2.5 to 4 | sd against 1.10 and mean against 0.10 |
| event correlations | `rho_zero` | added cells of long noise with correlation time 2 d or amplitude equal to the white level (guideline 7) | sd against 1.10 |

**The criteria, frozen before any regime runs.** 2,500 curves per cell (planned power at least 0.90 to detect 0.05 past the bound
at level 0.05, for a kurtosis near 3.5). An **accepted baseline**: simultaneous intervals of mean and variance over these cells (studentized max-t, familywise 0.05) wholly inside the
tolerances; a baseline not accepted leaves the item open. The sabotage's paired whole-curve 95 % interval excluding the protected bound; mean, sd and availability reported. The 0.05 distance is the planned effect, not a deletion
threshold.

**Failure to show a regime blocks completion of that item.** It is resolved only by a recorded, validated simplification with its own
acceptance, or by another prospectively specified regime; a mechanism kept in the code without either does not satisfy guideline 7.

**The longer noises also test `MAX_LAG = 5`.** If the correlations beyond it change the sd of a certified group statistic by 0.02
or more, the permission for that noise model is blocked pending a recorded revision.

## 5. The sinusoid: the false-alarm limit wins

Round 1 showed that a frequency-consistency gate cannot be justified from E3's population, and round 2 that a residual below
3 sigma is a non-detection, not evidence that the variability explains the dip. **The rule requires positive evidence of attenuation.**

`box_after`: the box depth at the candidate's ephemeris on the undetrended normalized flux with the complete joint model (offsets,
tested harmonics and extra frequencies, fitted out of transit, as the test does) subtracted. Its error is the fixed-linear-fit form
`sigma_r^2 = a^T (I - H) Sigma (I - H)^T a`, where `H` fits out of transit and predicts over the whole series, and `Sigma` is the
out-of-transit white and `beta`-scaled covariance. Frequency selection is not in it; the evaluation below measures its effect.

For a flagged harmonic (the v0.5 rule: significance above 15, semi-amplitude at least half the depth `D`):

- **FAIL (warning)** only with valid coverage of the in-transit and baseline cadences and `box_after + 3 sigma_r < 0.5 D`: the residual
  is measured small enough that the variability removes at least half the dip.
- Otherwise **INCONCLUSIVE (`ambiguous_sinusoid_with_transit`), in every denominator.** Never PASS.
- Not flagged: PASS only under the existing detectability requirement, recomputed for this decision; otherwise INCONCLUSIVE.

This is an empirical rule pending validation; its false alarm is what the evaluation measures, not a consequence of its construction.

**The changed rows, stated.** Rows 3.1, 3.4 and 3.6 (the variability explains the dip) keep their FAIL requirements, reached through
the positive evidence above. Row 3.8 (a) on a planet curve with an exact harmonic and row 3.2's detectability requirement stop being FAIL
cases and become INCONCLUSIVE: that is guideline 3, reported as a changed row. Row 3.8's sub-check flag counts are reported apart from
final FAIL outcomes. The old amplitude-only sensitivity block is replaced by the measured sensitivity of the new decision.

**The evaluation, frozen before it runs (separate development seeds).** The composite null is a planet on a star with a stellar sinusoid:
separation from the tested harmonic (0, 0.002, 0.01, 0.05 relative), amplitude (0.5, 1, 2 times the depth), phase (0, a quarter period), noise
(white, correlated), gaps (none, TESS-like), 1,109 curves per cell, plus the same grid with search-recovered periods and a full-chain run. The
claim is **per cell**: zero false FAILs gives an upper bound of 0.0027 in that cell; no mixture is claimed. **A false FAIL in any cell withdraws
FAIL from the rule altogether** (flagged cases become INCONCLUSIVE) before acceptance, and the rows requiring FAIL then fail their acceptance: they are not waived. D1's two conditions are measured separately for V1 and
V2, with their paired v0.4 comparator and paired uncertainty.

## 6. T3b

Frame: a **TOI false positive whose target is independently catalogued as an eclipsing binary or candidate**: it is not called verified, nor
is the binary said to have caused the TOI signal, nor the distribution called equal to the old frame's.

**Identity.** By TIC for TESS-EB and T10K. For Gaia DR3 `vari_eclipsing_binary`, whose table carries no TIC: an **established TIC-to-Gaia
association** (the TIC's own Gaia identifier, with the DR2-to-DR3 mapping), fixed at the selection stop, with its release mapping and ambiguity
handling; an unresolved identity makes the target ineligible. A nearby Gaia EB alone is not a catalogued target. **Period consistency** with the
TOI period (within 1 %, of the period, its double or its half) is required for T10K and Gaia, fixed before any draw; TESS-EB keeps its frozen
rule, the asymmetry stated. Missing or conflicting periods: not eligible. **Eligibility is the union of the memberships that qualify on their
own; the label's precedence (TESS-EB, T10K, Gaia) is applied afterwards, for display only. All memberships, identifiers, periods and conflicts
are retained.**

**The inventory** ([`stage2/t3b-inventory.json`](../validation/v0.5.2/stage2/t3b-inventory.json), counts only, frozen v0.5 TOI table, TOI-table
positions): 856 false positives; TESS-EB 63 members, 22 never walked; T10K adds 0 eligible false positives (7 of its 10,001 systems are TOI hosts, none a
false positive); Gaia, position-only proxy, at 2 arcsec adds 3, 0 of them with a single Gaia EB and period consistency; at 21 arcsec (one TESS pixel, not
admitted by any identity rule) 105, 54 of them unique and period-consistent. The established association can only remove members from the proxy's
counts, so the Gaia addition at the identity rule is 0 today. At v0.5's yield (11 of 41, interval 0.14 to 0.43) the pool forecasts about 5.9 acceptances
against 11. **This is a shortage forecast, not an infeasibility finding:** twenty-two unwalked stars could produce eleven. It goes to the maintainer at
the protocol stop, with these counts, after the TOI table's refresh.

## 7. Running the work

[`stage2/driver.py`](../validation/v0.5.2/stage2/driver.py), revised after round 2. Dispatch unit by unit. **A batch lasts at most 30 minutes and nothing
is interrupted (the maintainer's item 10):** a run declares its shards' limit from dispatch to completion, worker start included, and dispatch stops that long before the end. A shard beyond its limit is kept,
recorded as a deviation and stops the run; the 30 minutes hold while the declared limit holds. **A stop binds:** passing the cap by 10 %, a failed accounting or a shard beyond its limit stay in `stop.json`, and neither the run
nor its bytes can be used until a reason is recorded, even with every shard present. **Consumption:** user and kernel time of the owned workers through process handles kept from the first sight
of each, plus the controller's time, written every 20 s apart from the results, with the workers' identities. A failed query stops dispatch and charges every worker for the elapsed time. After a crash every worker ends by itself as soon as its controller is gone, the restart is refused while any worker of the
open batch is alive, and that batch is charged every worker for a whole shard's limit and one more interval. Dispatch reads consumption at that moment. The watchdog stays alive until every worker has stopped, exception paths included, and ends them above 110 %. The controller
refuses processors outside 8 to 31, and each worker checks its own priority and affinity. A shard is validated against the run's fingerprint (hashes of the
code, table bytes, source manifest, `uv.lock`, versions) and its argument. Science bytes and timing are separate. Tests:
[`tests/test_v052_driver.py`](../../tests/test_v052_driver.py) (kill mid-run resumed with another worker count and compared by bytes; crash accounting; live cap;
watchdog; batch expiry; a shard beyond its limit; worker exception; failed time query; truncated, corrupt, missing, stale and foreign shards; a result without its
sidecar; a leftover temporary file; error outcomes). Logical processors 8, 10, ... 30 are 12 distinct physical cores (`stage2/topology.json`).

## 8. Caps

The numeric worksheet is produced from the cost probe of a prototype of the final unit, section by section, before any acceptance: development probes, sizing,
known-answer validation, all acceptances, references, sabotages, the remaining work packages, calibration, reviews and disk, **net of what stage 2 already spent**. The
three limits are distinct: the 30 % allowance is a planning margin added to each section's projection; 1.5 times the projection stops a section; 10 % above an
experiment's cap ends its workers. None overrides the hard maxima. **A projection above a hard maximum is a STOP before that workload is launched.**

**A first projection, which decides nothing** ([`stage2/projection.py`](../validation/v0.5.2/stage2/projection.py)): the v0.5.1 per-curve cost at one worker, plus four
extra detrendings per curve and sector group at the current cost: 3,361 CPU-h at `T` = 8,000, 3,781 at 9,000, 4,201 at 10,000, against the hard maximum of 2,000. The comb is
about three quarters of it.

**What the route gave** ([`probe-a0v4-cost.json`](../validation/v0.5.2/stage2/probe-a0v4-cost.json), [`probe-workers.json`](../validation/v0.5.2/stage2/probe-workers.json), development seeds, version 4 with the comb). The acceptance of A0 at `T` = 9,000 (9,669,446 curves) is projected at **1,416 CPU-h**, measured at
12 workers, one per physical core, against the first projection's 3,781. A first version solved a whole segment at once and cost 3.3 times more CPU per unit at 12 workers than at one (7.4 times at 22); blocks of 24 knots leave 1.25 times at 12 workers and 2.33 times at 22, at the same throughput (44,756 and 43,450 units per hour),
so **12 workers is the placement**, and 22 buys nothing. The faster code's numbers: [`fast-detrend-equivalence.md`](../validation/v0.5.2/stage2/fast-detrend-equivalence.md). Revision 1 passed on a scope Codex found too narrow; revision 2 **failed one frozen row** (a tied epoch label), and that failure stands for its code; revision 3, on corrected code under the unchanged criteria, with fresh seeds and one permitted run, passed every row
([`fast-equivalence.json`](../validation/v0.5.2/stage2/fast-equivalence.json); largest flux difference 1.3e-14, tolerance 1e-11). Versions 2 and 3 are unchanged on [21 projections](../validation/v0.5.2/stage2/compat-v3.json) against the source before version 4; that is evidence on those projections, not a proof for every input.

**The route, in this order.** (1) A reproducible baseline, and the measured CPU per unit at 1, 12 and 22 workers. No saving is claimed from the worker count until measured:
the projection already uses one-worker costs. (2) Faster code **with the same numbers**: the same operations and conventions (masks, clipping, gaps, fitting thresholds);
numerical comparison with tolerances frozen before evaluation, on curves including ones near decision boundaries; identical availability, branch choices and covariance
validity decisions, and identical final outcomes; byte identity where exact equivalence is claimed, otherwise the tolerance is stated, with the reference code as a fallback near a
boundary. **`J` stays 4:** a smaller comb is a method revision that would need its own calibration, sabotage, availability and sensitivity checks, and would not solve the
budget alone. Grouping of strata is not used. **If the measured projection stays above a hard maximum, the work stops and goes to the maintainer with the numbers;** no target,
tolerance or size moves to fit the budget.

## 9. Order

1. Finalize this design (methods, family, validation criteria, candidate-selection rules, budgets) with Codex.
2. The sizing evaluation (section 1): fix `T`, `G_min` and the schedules, before the code (guideline 1).
3. Implement version 4 in isolated paths, with the byte-compatibility proof for version 3 and the numerical equivalence of any faster code.
4. The development probes, under the criteria frozen above: `f`, cost, sectors, the sinusoid evaluation and V families, the regimes of section 4, and the adequacy check of section 1 (a failure is a STOP), priced first.
5. The numeric budget, with a STOP if over.
6. Freeze the known-answer gate's criteria (the stage-1 text, unchanged) and evaluate them only after that.
7. Validate the inference machinery at the chosen size (the stage-1 gate).
8. Freeze the final code, the complete acceptance specification and the numeric budget.
9. The acceptance runs, once each. WP2 and the other acceptances, then the combined gates with D1's two 0.10 conditions.
10. The protocol draft, and the maintainer's stop.

A later probe that contradicts a sizing or method assumption is a STOP and a prospective, recorded redesign. Fresh development data can support a new design; they never turn a failed frozen
assessment into a passed one.
