# v0.4 acceptance documents (WP0)

Written on 2026-10-29, **before any code** of v0.4 ([plan](v0.4-pilot-plan.md), issue #177).
For each work package: what is accepted, how it is measured, and the synthetic cases that must
pass and must fail. Every case here runs offline, on synthetic data or recorded fixtures (the
CI rule: no test depends on the network). A WP is accepted when its cases exist as tests, pass,
and the counts come from a JUnit XML file.

Scientific parameters (domain, grid, thresholds, promotion rule) are **not** fixed here: they
belong to the protocol, approved at P1. The cases below use placeholder values and check the
mechanism, not the values.

## WP1: test roles, temporal diagnostic, method status, completeness (#174)

**Accepted when** a v0.4 claim can declare a role for each test and a stage for each test, the
verdict aggregates only decisive tests with the rules of `docs/verdicts.md` unchanged, and the
required fields are present everywhere.

| # | Case | Must |
|---|---|---|
| 1.1 | decisive tests all PASS with coverage; `holdout_by_year` (diagnostic) FAIL | verdict SURVIVED; `temporal_diagnostic.state = "fail"` |
| 1.2 | the same with the diagnostic PASS, then INCONCLUSIVE, then not run | verdict identical in all three (SURVIVED); states `pass`, `inconclusive`, `not_run` |
| 1.3 | a diagnostic PASS with zero coverage | the diagnostic is INCONCLUSIVE (never PASS); verdict unchanged |
| 1.4 | a required diagnostic absent from the results | case marked **incomplete**; verdict unchanged |
| 1.5 | a decisive fatal FAIL after a passing gate | REFUTED (as today) |
| 1.6 | a claim without roles (every v0.2 fixture) | exactly today's verdict and reason, and a byte-identical `verdict.json` (no new field is added to a claim without roles) |
| 1.7 | a stage-1 run: pixel tests deferred | each deferred test INCONCLUSIVE, coverage 0, reason "not run at this stage"; never PASS; verdict INCONCLUSIVE unless a fatal FAIL or a gate failure decides first |
| 1.8 | a stage-1 run with a fatal FAIL (for example `odd_even`) | REFUTED; promotion state recorded apart from the verdict |
| 1.9 | `method_status` | present and equal to `not_validated` in `verdict.json`, the report, the exporter output and the ledger entry, with the reference to the v0.2.1 closing record |
| 1.10 | a v0.4 claim where a test is declared both decisive and diagnostic, a test has no role, or a required diagnostic is not listed among the claim's tests | the claim is refused at load time |
| 1.12 | integration through `conclude_analysis`: `expected_tests` returns the decisive tests and, apart, the required diagnostics; the verdict is computed from the decisive tests only; presence, role, coverage and aggregation checked together on one synthetic analysis | the holdout result reaches `temporal_diagnostic` and never `aggregate`; a missing decisive test still gives INCONCLUSIVE; a missing diagnostic marks the case incomplete |
| 1.13 | the severity a test emits (for example `secondary_eclipse` warning or fatal by depth ratio, `plausibility` fatal for the radius and warning for the duration) | aggregation and promotion use the emitted severity, never a fixed one from a table |
| 1.11 | **#30**: the resolved hashes of the recorded v0.1, v0.2 and v0.3 claims | unchanged by the new schema; earlier locks still verify (`tests/test_canonical_lock.py`, `tests/test_lock_compat.py`, `tests/test_verify_locked_tags.py` stay green) |

**Must fail (sabotage checks):** a patched aggregator that lets a diagnostic FAIL reach the
verdict makes 1.1 fail; a patched coverage rule that lets a zero-coverage diagnostic PASS makes
1.3 fail; dropping `method_status` from the exporter makes 1.9 fail.

## WP2: frame, selection, retries, deduplication (#22, #27, #172)

**Accepted when** the selection is a deterministic function of the frame snapshot, the catalog
snapshots and the drand seed, and every rejection has a reason.

| # | Case | Must |
|---|---|---|
| 2.1 | the same synthetic frame, snapshots and seed, run twice | identical walk order, accepted list and log (bytes) |
| 2.2 | a frame with duplicate sort keys | refused (`refute.drand.shuffled` raises) |
| 2.3 | a star with a TOI, a CTOI, a confirmed planet, or an EB-catalog entry in the snapshots | excluded with the matching reason; counted in its own denominator |
| 2.4 | a star failing an availability rule (a sector without a light curve; fewer years than required; a missing TIC field) | rejected by availability, never by any signal-dependent test; reason recorded |
| 2.5 | a transient error, then success within the retry policy | accepted; the failed attempts logged |
| 2.6 | transient errors on every attempt | the walk **stops** (no skip), with the state written for the maintainer |
| 2.7 | a known target of an earlier phase (calibration, development, pre-document runs, v0.2.1 gate 3b) | excluded before the shuffle; the exclusion list is checked against its sources and the script stops if they differ |
| 2.8 | deduplication: a found signal at a known TOI's period, or at 2x, 1/2x, 3x, 1/3x of it, within the declared tolerance, on the same or a nearby star | matched, with the alias named; coverage = catalog rows scanned (> 0) |
| 2.9 | deduplication with an empty or missing snapshot | INCONCLUSIVE (coverage 0), never "no match" |
| 2.10 | a snapshot larger than 5 MB | not written to git; its SHA-256, URL and retrieval time are; the archive manifest is checked |

**Must fail:** removing the availability-only restriction (letting a signal-dependent test
reject a star in selection) makes 2.4 fail; turning a transient error into a rejection makes
2.6 fail.

## WP3: injection-recovery and transformed curves (#175, #9)

**Accepted when** injections enter before detrending, recovery uses the identity rule, and the
counts are published per curve with denominators and intervals.

| # | Case | Must |
|---|---|---|
| 3.1 | a synthetic curve (white noise plus a stellar trend), a high-SNR box transit injected before detrending | recovered: period within tolerance, epoch within tolerance, gate PASS |
| 3.2 | the same transit far below the noise | not recovered; counted in the denominator, never dropped |
| 3.3 | a recovery at 2P or P/2 | counted as a declared alias, apart from exact recovery |
| 3.4 | the injection seed | derived deterministically from the protocol's seed and the star's identifier; two runs give identical grids |
| 3.5 | the grid and the number of injections in the run | equal to the locked values; a mismatch stops the run |
| 3.6 | inverted curve of a curve with a real box transit | the dips become peaks; the stage-1 counts of the inverted curve are reported apart |
| 3.7 | the protocol's scrambling transformation (per-sector cyclic rotation, as proposed for P1): (a) a fixed seed; (b) a synthetic multi-sector periodic signal with offsets fixed in the test, chosen so that the phases differ between sectors | (a) deterministic offsets; (b) the phases of the rotated signal differ between sectors as the fixed offsets predict, and a signal with several transits inside one sector stays visible (documented as a limit); loss of coherence is never asserted for drawn offsets |
| 3.8 | per-curve output | counts, denominators and 95% Wilson intervals; the gate count and the survival count apart; no pooled interval presented as 95% coverage |
| 3.9 | a star without pixel files (funnel stage 1) | the transformed curve goes through the light-curve tests only; pixel tests INCONCLUSIVE with coverage 0; never counted as passed |
| 3.10 | a transformation applied to a synthetic multi-sector record with every input (PDCSAP and SAP with errors, background, quality flags, centroids, momentum dumps, and pixel cadences with different aperture shapes, target positions, CROWDSAP and FLFRCSAP per sector; and a momentum dump on a cadence that the quality mask removes) | all per-cadence columns transformed jointly by the same rule, on the raw cadence grid, before the quality mask; the masked dump moves with its cadence; time stamps, cadence counts, per-cadence alignment between light curve and pixels, and every per-sector metadata value preserved; a test reading an untransformed auxiliary series is impossible (checked by a sabotage that skips one series) |
| 3.11 | degenerate draws (a rotation equal to the identity in a sector, two rotations of one curve with the same offsets, a sector below the protocol's minimum length) | identity impossible by the offset range; a repeated vector redrawn by the protocol's rule, then INCONCLUSIVE after its limit; a short sector left unrotated and reported |

**Must fail:** injecting after detrending makes 3.1's chain check fail (the detrending step must
see the injected flux); dropping unrecovered injections from the denominator makes 3.2 fail.

## WP4: transit-duration uncertainty (#176)

**Accepted when** the exporter writes the duration with its uncertainty and method, or a
justified absence, and the method meets predefined synthetic cases.

| # | Case | Must |
|---|---|---|
| 4.1 | synthetic transits with known duration at several SNRs | the true duration inside the reported interval at the method's nominal rate, within the binomial acceptance band, over the fixed set of seeds |

Before any WP4 code, a method specification is committed: the estimator, the nominal interval
(for example 68 %), the set of seeds and SNRs, the number of trials, the acceptance band (the
binomial 95 % band around the nominal rate for that number of trials) and the estimability
criterion of 4.2. Case 4.1 is checked against those values, not against values chosen after
seeing the results.

| # | Case | Must |
|---|---|---|
| 4.2 | a transit whose duration is not estimable under the method's criterion (too few in-transit points, or an unresolved ingress) | `duration_err_hours` absent with an explicit reason; never a number |
| 4.3 | the gate passes but the duration is not estimable | justified absence (passing the gate is not enough) |
| 4.4 | the exporter output | the method name and version next to the value; still says that nothing was submitted |

## WP5: ledger, case files, self-contained dossiers, report wording (#25, #161, #23)

**Accepted when** the ledger verifier checks the chain and the per-case checklist, and every
dossier carries what its review needs.

| # | Case | Must |
|---|---|---|
| 5.1 | a ledger of synthetic events | the verifier recomputes every `prev_hash` and passes |
| 5.2 | one byte of an earlier event changed | the verifier fails at that event |
| 5.3 | an event removed from the middle | the verifier fails |
| 5.4 | a correction | a new event pointing to the corrected one; the old event stays |
| 5.5 | a light entry of a stage-1 star | has `method_status`, `temporal_diagnostic`, the stage-1 results and the promotion state apart from the verdict |
| 5.6 | a complete case missing one item of the case format (identity, question, alternatives, data, cross-match, analyses, coverage and limits, uncertainties, review, questions for a human, conclusion) | the checklist reports the missing item; the case is incomplete |
| 5.7 | a conclusion outside the closed vocabulary | refused |
| 5.8 | a self-contained dossier | the annexes cited by hash are inside the sealed core, with the selection-log excerpt of the target; `refute check-dossier` passes; removing one fails it |
| 5.9 | the holdout section of a report | states that the hidden year is detrended once before any logged read (#23) |
| 5.10 | `refute discover` (or the script chosen in WP1) on a synthetic claim | produces a dossier identical to `execute_run` on the same claim |

## Phase acceptance (the gate checks these with evidence)

1. Every case (controls and promoted stars) complete: the checklist gives 0 missing items.
2. `refute check-dossier` passes on every dossier; a rerun from `REPRODUCE.md` in a clean
   checkout, with a fresh download, gives identical data hashes and `key_values` equal within
   1e-6.
3. Controls: the identity of the catalogued signal evaluated and reported, whatever the result.
4. Every one of the N funnel stars has a light ledger entry; download failures are
   INCONCLUSIVE with a reason; denominators (eligible, promoted by the cap, survivors) reported.
5. Injection and transformed curves: per-curve counts and rates with denominators, intervals
   and the declared sampling unit; across curves descriptive only; grid and budget equal to
   the lock; scope declared.
6. Deduplication: every exploration signal cross-matched against TOI, CTOI and confirmed
   planets (dated snapshots), coverage > 0, result in the ledger.
7. Ledger: every event of every case, chain verified, anchored in a published commit.
8. Exporter: duration uncertainty with its method, or a justified absence. *(ROADMAP v0.4
   amendment 5, 2026-10-29: in the pilot, the justified absence citing the failed acceptance of
   `trapezoid-least-squares-1`; no other method in this phase.)*
9. Review: one independent report per dossier, attached, with every objection treated or
   tracked in an issue.
10. Gate: an independent review returns SURVIVED, or WEAKENED with its issues open.
