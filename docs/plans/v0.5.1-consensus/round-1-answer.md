## Verdict: WEAKENED

The correction direction is credible, and the records mostly support the draft’s counts. I would **not treat the scope as settled for code yet**. The feasibility rules need stronger limits, the binary branch needs an actual correction path if it is deemed feasible, and several acceptance and budget protections need objective rules.

## Objections

1. **Critical, WP1 does not yet justify infeasibility decisions.** The D1 bound is valid in the simple Gaussian, shared covariance case, but the draft applies it to a nearest-planet fit with nuisance parameters and then uses the result to estimate a target-level PASS probability. The classic Neyman–Pearson result concerns specified hypotheses; the paper distinguishes simple from composite hypotheses and notes that composite alternatives need additional treatment. [Neyman and Pearson (1933)](https://www.stats.org.uk/statistical-inference/NeymanPearson1933.pdf) The D2/D4/T2a “rule floor” also covers only selected alternatives, so it cannot yet establish that *no estimator in the family* could improve the result. For T2a, a real light curve does not provide a known “true noise model” from its measured scatter alone. The fixed 0.05 cutoff is honest as a preregistered decision only if the estimated probability and its uncertainty are defined.

   **Change required:** Specify the Gaussian model, covariance, nuisance-parameter treatment, and how candidate search and eligibility enter the oracle. Calculate a conservative bound on each target’s PASS probability, including finite-sample uncertainty, and state what happens if the bound crosses 0.05. Recast the D2/D4/T2a calculation as a valid optimistic bound on the whole target, or do not use it to declare infeasibility. [Plan, section 4](/C:/Projetos/refute/docs/plans/v0.5.1-plan.md:113)

2. **Critical, a feasible EB result has no defined correction path.** The record shows that 33/35 EB1 survivors and all 40 EB2 survivors were folded at half the true period. The draft’s own rough calculation leaves about 24.6 EB1 and 20.4 EB2 survivors even with its assumed duration bound, above the D1 allowance of roughly 11. WP2 may catch alternating-depth cases, but it cannot address near-equal folded binaries by that mechanism. Section 9’s #10 option is only a warning, and the scope does not specify a decisive duration correction if WP1 says either EB target is feasible. The rough calculation is a useful risk signal, not a validated lower bound: it assumes a 3-sigma odd/even rule and a perfect duration filter. [Plan, section 2.5](/C:/Projetos/refute/docs/plans/v0.5.1-plan.md:71) [C1 generator, EB families](/C:/Projetos/refute/src/refute/packs/tess/calib05/c1.py:263)

   **Change required:** Before WP1, define the correction route for every feasible EB target, including the folded, near-equal case. If the proposed route is a duration or stellar-density test, give it an acceptance plan and a non-regression check for planets. A warning may move an outcome from SURVIVED to WEAKENED under the existing aggregation, but it must be validated and reported as such, not treated as evidence that the binary was refuted.

3. **Important, the WP2/WP3 coupling rule is not a sufficient guard as written.** Checking the combined changes on development seeds is sensible, and a fresh C1′ confirmation can detect regressions. But “at risk” has no numerical definition, the stop invokes a later Codex decision, and the coupling list omits D3 and D5 even though those are promised non-regressions. [Plan, sections 1.2 and 3](/C:/Projetos/refute/docs/plans/v0.5.1-plan.md:32) [Coupling rule](/C:/Projetos/refute/docs/plans/v0.5.1-plan.md:100)

   **Change required:** Freeze objective combined-code acceptance gates before code. Include D1 for SE, V1, V2, ER and NR, plus D3 and D5; define how each gate treats SURVIVED, WEAKENED and INCONCLUSIVE. Keep the development screen separate from the unseen acceptance run and the final fresh confirmation. The 39 SE, 39 EB1 and 67 EB2 cases with INCONCLUSIVE and no decisive FAIL are a risk inventory, not a prediction that one fix releases all of them. The 34 diagnostic single-event FAILs among 45 SE INCONCLUSIVE outcomes are promising evidence, but that test is currently diagnostic.

4. **Important, the covariance diagnosis is right about the computation but too certain about the cause.** `aperture_blocks` draws core and large-aperture depths independently, then uses the quadrature error for their difference. `systematics_blocks` likewise draws SAP and PDCSAP measurements independently. That confirms the computation defect. [power.py, aperture simulation](/C:/Projetos/refute/src/refute/packs/tess/power.py:87) [power.py, SAP/PDCSAP simulation](/C:/Projetos/refute/src/refute/packs/tess/power.py:153) Positive covariance from shared photons would reduce the variance of a difference, but the draft has not established the full covariance, including pipeline processing and other systematics. Thus “same photons” is a plausible mechanism, not yet a measured causal result.

   **Change required:** Estimate or validate the joint error model on suitable paired measurements and synthetic controls, including correlated-noise cases. Keep the same rejection region and alternative, as proposed, and freeze its acceptance before code.

5. **Important, WP3 needs to show how its changes can actually move D2, D4 and T2a.** The record-derived counts are correct: C1 family P has 83/186 eligible INCONCLUSIVE outcomes, and the listed test incidences match the diagnosis file; C2 records 586 systematics, 325 sinusoid and 285 odd-even incidences among 631 INCONCLUSIVE injections. These are overlapping incidences, not unique causes. The odd/even calculation is a reasonable Gaussian approximation, but the 10–18% estimate should be labeled illustrative, not a measured floor. [diagnosis.json](/C:/Projetos/refute/docs/plans/v0.5.1-wp0/diagnosis.json)

Apply checks where each harmonic is in domain, report the others separately, and never let “not applicable” silently count as PASS or remove cases from target denominators. If no harmonic is covered, preserve that as unresolved coverage or explicitly extend and accept the domain. For **#204**, measuring false box preference is the right concern, but merely increasing 50 simulations may make the 0.86 estimate more precise without making the current 0.90 sensitivity requirement pass. Freeze a calibrated alternative and rejection rule that addresses the observed false preference; any conditioning on the observed statistic needs a prespecified selective-inference justification. Do not tune to the favorable observed statistic.    **Change required:** Freeze minimum sample sizes and a precision rationale before code. If the minimum design cannot fit, stop before confirmation. Preserve per-star reporting and the star as the cluster unit for C2. Reconcile the 39.13-hour source value in the plan.
