# Verdict: WEAKENED

Amendment 1 is directionally justified, but the acceptance document still has gaps that could invalidate error calibration or let tests pass without demonstrating the intended protection. I did not modify files or run project code.

## Numbered objections

1. **Critical, A0 treats correlated measurements as independent.** A0 measures event errors on pseudo-events, then propagates group means and differences as independent across sectors and events ([acceptance, lines 48–60](/C:/Projetos/refute/docs/plans/v0.5.1-acceptance.md:48)). That independence is not justified in correlated noise. The `max(model, empirical)` rule by itself tends to reduce significance, making a real effect less likely to FAIL and more likely to be INCONCLUSIVE. But ignoring covariance can understate an error, including for negatively correlated measurements, and cause false FAILs. The 400-curve pull cases do not explicitly cover covariance across events and sectors at the candidate’s cadence and coverage.

   **Required text change:** Replace the last sentence of A0 with: “Group means and differences use the covariance of event measurements across sectors and events, estimated by the same estimator on coverage-matched pseudo-event groups. If that covariance cannot be estimated or validated, the result is INCONCLUSIVE. Acceptance tests must include the candidate’s event spacing, sector boundaries, and unequal event coverage under correlated noise.”

2. **Important, A0’s coverage scaling is underspecified and relies on an unverified noise assumption.** The procedure rescales each pseudo-event by `sqrt(n_i / n_ref)` ([acceptance, lines 54–60](/C:/Projetos/refute/docs/plans/v0.5.1-acceptance.md:54)), but does not define `n_ref` or say how the resulting reference-coverage error is converted to the error for each real event. That scaling standardizes errors only under an inverse-square-root coverage model; correlated noise and different cadence geometry can break it. A0.4 varies trend between sectors, but does not validate coverage scaling across event-level coverage patterns ([acceptance, lines 68–74](/C:/Projetos/refute/docs/plans/v0.5.1-acceptance.md:68)).

   **Required text change:** Define `n_ref` and explicitly state the conversion from reference coverage to each real event’s coverage. Add acceptance cases with multiple coverage levels and correlated noise; require pull calibration in each level. Otherwise, measure errors directly on pseudo-events matched to each real event’s coverage.

3. **Critical, the constant-series shortcut creates a loophole in `systematics`.** When the SAP-minus-expected series is constant, the document says its error is zero and declares any alternative difference “detectable” ([acceptance, lines 116–122](/C:/Projetos/refute/docs/plans/v0.5.1-acceptance.md:116)). Exact equality in a finite synthetic or observed series does not establish zero measurement uncertainty. An implementation could return zero error and claim guaranteed sensitivity, bypassing the intended false-failure and sensitivity checks.

   **Required text change:** Replace the constant-series rule with: “A zero empirical scatter does not establish zero error. Use the model-error floor; if both model and empirical errors are zero or not estimable, return INCONCLUSIVE (‘error not measurable’). Detectability is evaluated using the same finite-error model and prespecified alternative as other cases.” Add a test where the measured difference series is constant but the underlying measurement has nonzero noise.

4. **Important, two acceptance cases permit weak or vacuous passes.** WP2 case 2.7 accepts either FAIL or INCONCLUSIVE on every eligible SE curve ([acceptance, lines 94–99](/C:/Projetos/refute/docs/plans/v0.5.1-acceptance.md:94)). Since D1 counts SURVIVED only, making these cases INCONCLUSIVE can satisfy D1 without demonstrating that `single_event` catches detectable single-event signals. Likewise, WP3(d) case 3d.4 only requires a binary FAIL rate at least as high as the v0.5 rate ([acceptance, lines 193–201](/C:/Projetos/refute/docs/plans/v0.5.1-acceptance.md:193)). That rate could be near zero.

   **Required text change:** For 2.7, require `single_event` to FAIL on every SE curve whose candidate has adequate coverage and whose event alternative is detectable; permit INCONCLUSIVE only for an explicit coverage or sensitivity limitation, and report that fraction. For 3d.4, specify a minimum FAIL rate for each detectable binary case using the binomial-band convention; require subthreshold cases to remain INCONCLUSIVE unless the observed effect meets the existing rejection rule. Keep the v0.5-rate comparison as an additional non-regression check.

5. **Important, duration physics and uncertainty propagation need one correction.** The central-transit `T_max` with `b = 0` is the right maximum for the stated circular-orbit comparison ([acceptance, lines 209–213](/C:/Projetos/refute/docs/plans/v0.5.1-acceptance.md:209)). The `2^(1/3)` duration ratio and `T_max ∝ R M^(-1/3)` propagation are small-`R/a` approximations, not exact identities. The rule also derives `k` from fitted depth but does not include depth uncertainty in `sigma_Tmax`. Those omissions can change whether the warning is detectable or crosses its threshold.

   **Required text change:** Specify the exact duration ratio from the stated `asin` expression for the tested period and stellar parameters, using `2^(1/3)` only as an explicitly labeled small-`R/a` approximation. Propagate uncertainty in radius, mass, and fitted `k` (including any covariance used), or state and validate a justified bound showing the omitted terms cannot affect the decision. Make the D.3 detectability criterion use that same full uncertainty model.

6. **Important, WP3(c)’s rewording overstates what “0 of 240” establishes, and its evidence is not reproducible from the cited diagnosis files.** The acceptance text says the BIC-penalty hypothesis “does not hold” based on 240 synthetic curves ([acceptance, lines 170–178](/C:/Projetos/refute/docs/plans/v0.5.1-acceptance.md:170)). That result supports “not reproduced in these tested settings,” not a general conclusion. The supplied `diagnose_inconclusive.py` describes and runs C1 planet cases, not the 240 pure-sinusoid controls ([diagnosis script, lines 3–8](/C:/Projetos/refute/docs/validation/v0.5.1/feasibility/diagnose_inconclusive.py:3), [lines 47–71](/C:/Projetos/refute/docs/validation/v0.5.1/feasibility/diagnose_inconclusive.py:47)). I also verified 15 odd/even sensitivity refusals among the 75 identity-matched diagnostic planets in the records, consistent with the WP3(d) claim ([records](/C:/Projetos/refute/.cache/v051/diag/records.jsonl:16)); the JSON summary lists only its eight most common reason strings, so it should not be read as a count of all refusals.

   **Required text change:** Replace “the hypothesis … does not hold” with “the hypothesized failure was not reproduced in the 240 tested synthetic realizations.” Add the control-generation script, seed list, and result summary to the evidence record, and keep the reviewed real-control diagnosis as a separate pending step before WP3(c)’s acceptance section is written.

7. **Minor, the provenance for the amplitude S/N threshold is secondary and incomplete.** The document explicitly says Breger et al. was not read directly and identifies the later paper’s authors and year as unchecked ([acceptance, lines 37–43](/C:/Projetos/refute/docs/plans/v0.5.1-acceptance.md:37)). That is not adequate provenance for the cited attribution, though the threshold can still be adopted as a Refute convention.

   **Required text change:** Either provide a verified primary citation and complete bibliographic details for the later paper, or remove the Breger attribution and label S/N 4 solely as a prespecified Refute convention.

## Points that survive

- **Adding WP3(d) is justified in scope.** The forecast says the full-depth odd/even alternative is detectable for 98.9% of eligible development planets at the Cramér–Rao error ([forecast README, lines 21–30](/C:/Projetos/refute/docs/validation/v0.5.1/feasibility/README.md:21)), while the diagnosis supports an estimator-efficiency problem. The amendment keeps the existing rejection rule and alternative ([plan, lines 349–353](/C:/Projetos/refute/docs/plans/v0.5.1-plan.md:349)). No target or threshold is expressly relaxed.
- **The v0.5 rejection region is retained in most changed tests.** WP2 keeps its per-event rules ([acceptance, lines 76–95](/C:/Projetos/refute/docs/plans/v0.5.1-acceptance.md:76)); WP3(a) retains the stated rejection regions and alternatives ([lines 104–124](/C:/Projetos/refute/docs/plans/v0.5.1-acceptance.md:104)); WP3(b) retains the v0.5 warning thresholds ([lines 143–154](/C:/Projetos/refute/docs/plans/v0.5.1-acceptance.md:143)); and WP3(d) says it retains #185’s full-depth alternative ([lines 180–191](/C:/Projetos/refute/docs/plans/v0.5.1-acceptance.md:180)). The constant-series exception is the material exception.
- **The warning route and gate structure are directionally sound.** Duration warnings are explicitly nonfatal, and the plan requires reporting SURVIVED-to-WEAKENED transitions ([plan, lines 127–129](/C:/Projetos/refute/docs/plans/v0.5.1-plan.md:127)). The 100-per-family combined run is explicitly a screening-sized acceptance gate, with a second fresh set after a failed gate ([acceptance, lines 255–273](/C:/Projetos/refute/docs/plans/v0.5.1-acceptance.md:255)). Add the per-family low-eligibility rule explicitly: fewer than 20 eligible cases must be NOT DECIDABLE and must not satisfy a gate, as required by the v0.5 rule ([v0.5 acceptance, lines 414–418](/C:/Projetos/refute/docs/plans/v0.5-acceptance.md:414)).
