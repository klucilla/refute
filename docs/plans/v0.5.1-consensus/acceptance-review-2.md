# Verdict: WEAKENED

Revision 2 is candid about why revision 1’s shift rule would leave most measured cases inconclusive. But that feasibility result supports changing the rule, not the new rule’s statistical validity. The event-count scaling and overlapping grid still need calibration, and the stop rule requires a maintainer decision before A0 code is frozen.

## Objections

1. **Critical, the deviation exceeds the stated revision limit.** The plan allows at most one revision after Codex’s review and before code. Revision 1 used that revision. Recording revision 2 as a deviation is transparent, but does not resolve the stop rule. Also, the revision paragraph says “no test … changes,” while revision 2 adds row A0.5 and a sabotage check.

   **Required text change:** Replace “no test, threshold, alternative or case changes” with: “This deviation adds A0.5 and its sabotage check, and changes the shift-placement and validity rules. It is pending maintainer disposition under stop rule 1; A0 code must not be frozen until that disposition is recorded.” If the maintainer approves it, record that decision and then review the revised acceptance criteria.

2. **Critical, event-count scaling relies on the independence assumption the text says the shifts capture.** Scaling a group statistic by `sqrt(n_shift / n_real)` is appropriate only under conditions such as comparable per-event variance and variance falling roughly as `1/n`. Events being a period apart does not establish independence. Longer-timescale noise, detrending, and unequal event coverage or sector noise can correlate or weight events differently. For an odd/even difference, the stated effective count also assumes the groups’ event variances are comparable. This revives revision 1’s objection about scaling under unverified noise assumptions.

   **Required text change:** Replace the scaling sentence beginning “a group statistic of a valid shift is put on the real ephemeris’s footing” with: “Do not infer real-ephemeris error by event-count scaling alone. Estimate it from pseudo-event groups matched to the real groups’ event counts and coverage, or validate a specified scaling model against those matched estimates. A0.5 must require the pull bands to pass separately for the count-mismatch cases, stratified by group counts, event spacing, sector noise, and correlated-noise timescale. If the error cannot be calibrated for the real event pattern, return INCONCLUSIVE.”

3. **Critical, overlapping shifts can make the empirical scatter look more certain and smaller than it is.** A robust scatter estimator limits sensitivity to outliers; it does not correct for dependence among its samples. Nearby grid shifts can reuse many of the same cadences, yielding positively correlated statistic values and a scatter that understates the marginal noise. The stated threshold of 10 valid shifts counts placements, not independent information, so it is not meaningful as written. The model-error floor may mitigate this, but the acceptance text does not establish that it prevents false FAILs.

   **Required text change:** Replace “shifts may overlap each other (their values are then correlated, which the robust scatter tolerates)” with: “Shift statistics may be correlated; robust scatter does not correct for this dependence. A0.3 must define and validate a dependence-aware uncertainty estimate and effective shift count. Require at least 10 effective shifts for an empirical error; otherwise return INCONCLUSIVE.” A0.3 should make its acceptance check require that condition, rather than only checking placement and the nominal valid-shift count.

4. **Important, A0.5 and the provenance row do not support the claims made for revision 2.** A0.5 says the pulls of A0.2 pass and that the fraction below 10 is reported, but does not require pull calibration specifically among the curves with mismatched counts. Its sabotage claim that removing scaling “makes A0.5 fail” is therefore not guaranteed by its stated Must. The development JSON reports validity counts only and explicitly says it decides nothing; it does not validate the grid’s pull calibration. The provenance row calls the grid size and half-count “fixed by the development check,” which overstates what that check establishes. Also, A0.3 says “the same grid for every candidate,” although A0 filters that grid by candidate duration.

   **Required text change:** Change A0.5’s Must to: “For each prespecified count-mismatch and noise stratum, the scaled pulls pass A0.2’s bands; report nominal and effective valid-shift counts and the fraction below the required effective-count threshold.” Change the sabotage text to require that A0.5 fail when scaling is removed under those same strata. Change A0.3 to say “the same base grid for every candidate, with a candidate-specific exclusion mask,” and update the provenance row to state that the development check motivated the grid and validity choices but did not validate error calibration.

**Agreement:** The exact-event-count rule produced poor nominal availability in the cited development check, and the revision records that evidence instead of presenting it as calibration. The new design still needs maintainer disposition and acceptance criteria that establish calibrated errors under its dependence and coverage conditions before A0 code is frozen.
