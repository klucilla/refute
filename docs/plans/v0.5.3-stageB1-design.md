## 0. Where the code lives, and how its use is proven

**The code.** The estimators form a candidate battery, version 5, outside `src/`, in
`docs/validation/v0.5.3/stageB/battery_b1.py`. The rule is that nothing changes in `src/` or in
T2a's fingerprint without passing the stop. Codex's round 1 agreed that B1 need not enter `src/`.
If the forecast passes, porting version 5 into `src/` is part of the acceptance plan priced at the
stop. That port is a non-delegated step, since it changes the code hash.

**How version 5 is activated.** `battery_b1.activate(config)` replaces, in the calling process
only, the call targets that `pipeline_v52` uses for the four estimators. `deactivate()` restores
version 4 exactly, including configuration C's constants. Version 4's other consumers are not
touched: the patch replaces only the functions named in section 2, and only the call sites of
`pipeline_v52`. Then:

- **In every worker.** Every B1 script activates through the driver's importable initializer, or
  at the start of each shard, never in the controller only.
- **Recorded use.** Each record stores the active configuration (E1 to E4 on or off), each
  replaced function's source hash, and **counters of execution**: how many times each new path ran
  and which branch it took. Identity alone does not prove a call.
- **Order of runs.** Within a record, the comparators (v0.4, version 4) run with version 5
  deactivated. A test checks version 4, then version 5, then version 4 again, with identical
  version 4 results.

**The fingerprint** of each B1 run hashes:

- the code hash (`src/`, `pyproject.toml`, `uv.lock`);
- `battery_b1.py`, the run's script and `ledger_b.py`;
- this design;
- the configuration and the sample.

The code hash alone does not cover files outside `src/`, so they are hashed separately.

**Tests.** Synthetic tests with no network, in `tests/v053/` and run by CI:

- each estimator on injected signals with a known answer;
- E4's preservation of an injected background rise;
- the activation round trip (version 4, then 5, then 4).

## 2. The estimators (version 5)

Each one keeps version 4's statistic, rule and alternative. It changes how a quantity or its error
is computed, and nothing else. Each one is frozen here. None of its parameters moves after any B1
measurement.

### E1. A0's undefined variances: a conservative completion (`a0.group_variance`)

Version 4 returns no variance when a needed lag correlation has fewer than `MIN_PAIRS` pairs, or
when the estimated covariance is not positive semi-definite. Version 5 keeps every estimated
correlation that version 4 would use, and keeps version 4's model: correlations beyond `MAX_LAG`,
or across sectors and segments, are 0.

- **The order, frozen (Codex's round 2).** Version 4's `group_variance` runs first, unchanged, with
  its shortcut and its PSD tolerance. If it returns a finite variance, that variance is returned:
  every case version 4 decides by itself is kept. The extension runs only where version 4 refuses.
  It then builds the whole matrix of in-window pairs and records which correlations are estimated
  and which are missing.
- **No pooling and no matrix repair.** Codex's round 1 found both anti-conservative. Version 5
  instead bounds the unknown terms by Cauchy-Schwarz:
  - **Missing correlations only, and the matrix of the estimated terms is PSD:** for a pair
    `(i, j)` inside the lag window whose correlation is undefined, the term
    `2 w_i w_j σ_i σ_j r_ij` becomes `2 |w_i w_j| σ_i σ_j`, its largest possible value. The
    estimated terms are kept.
  - **The estimated terms' matrix is not PSD** (an inconsistency, with or without missing terms):
    every pair inside the lag window takes that bound. The matrix that decides this branch puts
    zero for the missing terms, and is used for nothing else (Codex's round 3).
- **What it bounds.**
  - When every in-window pair is bounded, the result is an upper bound on the variance under
    version 4's model, whatever the in-window correlations. Codex's case (unit errors, contrast
    (1, -1), true r = -0.5, variance 3) gets 4.
  - When only the missing terms are bounded, it bounds every completion compatible with the
    estimated terms that were kept. It does not bound the true variance if those estimates are
    wrong.
- **Calibration.** E1's domain had no calibrated permission in version 4. It needs its own null
  check (B1.3) and, later, the acceptance's. Each record stores which branch ran.
- E1's scalar bounds are never turned into a matrix for inversion (E2).

### E2. `odd_even`: the joint GLS contrast (`battery_v52.check_odd_even`)

The statistic stays in the box family, guideline 2 of v0.5.2: the per-event box depths, measured
exactly as in version 4, for both the real events and the pseudo-windows.

- **Version 4** averages each group with inverse-variance weights and takes the difference.
- **Version 5** estimates the odd-even difference `δ` jointly with a common depth `μ`, by GLS under
  A0's full covariance `C` of the measured events. The model is `d_i = μ + s_i δ / 2`, with
  `s_i = +1` for odd events and `-1` for even ones. Then:
  - `δ̂` is the second component of `(X^T C^-1 X)^-1 X^T C^-1 d`;
  - its variance is `[(X^T C^-1 X)^-1]_δδ`.

  This is the minimum-variance linear unbiased contrast under `C`. It minimizes the contrast
  jointly, not each group mean (Codex's round 1).
- **When version 5 uses that GLS (frozen numerical conditions; Codex's round 2).** All of these
  must hold:
  - version 4's `group_variance` returned a finite variance (every correlation estimated, within
    its PSD tolerance), and `C` is built from exactly those terms;
  - `C`'s Cholesky factorization succeeds;
  - `C`'s condition number (2-norm) is at most `1e8`;
  - the condition number of the 2 x 2 matrix `X^T C^-1 X` is at most `1e8`.

  The solution goes through the Cholesky factor (triangular solves), and `C^-1` is never formed.
- **Otherwise** version 5 keeps version 4's weights and variance. Where version 4 refused, it uses
  E1's bound.
- **E2 can change decisions version 4 took**, on purpose: a smaller variance can turn an
  INCONCLUSIVE into a PASS or a FAIL. B1.2 and B1.4 report every such change.
- **No local baseline.** Codex found no gain with symmetric coverage. Stage A's Fisher bound uses
  the true template, not boxes, so B1 does not claim to reach it. It reports
  `σ_δ(v5) / σ_oe(Fisher)` on the D2 losses as information.

### E3. The sinusoid's residual by GLS (`battery_v52.box_after_model`)

The design (one level per sector, a cosine and a sine at each tested and extra frequency) and the
masked fit are version 4's: `H` fits the out-of-transit cadences and predicts the whole series.
Version 5 changes two things.

- **The covariance model, per sector.** Observation `y_t = x_t + ε_t`, with `ε_t` white of
  variance `σ_w²` and `x_t` a stationary AR(1) in time, whose stationary variance is `σ_a²`. The
  correlation between two cadences is `φ^(|t_i - t_j| / δ)`, with `δ` the cadence. The dependence
  therefore continues across gaps and masked spans, as in the generator. Sectors are independent.
- **The moments (frozen).** They use the white fit's out-of-transit residuals, with the sector's
  mean removed:
  - `γ0` is their variance;
  - `γ1` is the mean product over pairs of out-of-transit cadences exactly one cadence apart
    (`|Δt - δ| < 0.1 δ`);
  - `γ2` is the same over pairs two cadences apart.

  Each needs at least 200 pairs. From them, `φ = γ2 / γ1`, `σ_a² = γ1 / φ` (the latent
  component's stationary variance) and `σ_w² = γ0 - σ_a²`.
- **The fit: a Kalman filter.** The filter starts from the stationary state (mean 0, variance
  `σ_a²`). Between consecutive cadences of the sector, at whatever spacing, it propagates
  `x` by `φ^(Δt / δ)`, with innovation variance `σ_a² (1 - φ^(2 Δt / δ))`, and observation
  variance `σ_w²`.
  - An in-transit (masked) cadence is propagated without an update.
  - An observational gap is propagated across its `Δt`. The filter is never restarted inside a
    sector.
  - The filter's standardized innovations whiten `y` and each column of the design. The GLS
    solution is least squares on the whitened arrays, by QR (never the normal equations), which
    builds `H` from the out-of-transit cadences.
- **The residual's variance.** `u = (I - H)^T a` is computed explicitly (one vector). Then
  `u^T Σ u = σ_w² Σ u_i² + σ_a² u^T K u`, with `u^T K u` accumulated in `O(n)` by the running sum
  `R_i = φ^((t_i - t_{i-1}) / δ) (R_{i-1} + u_{i-1})`, with `R_1 = 0`, so that
  `u^T K u = Σ u_i² + 2 Σ u_i R_i`, accumulated separately per sector (Codex's round 3). **Whitening** (multiplying by
  `Σ^(-1/2)`) and **multiplying by `Σ`** are two separate recursions. A deterministic test
  compares both with dense matrices on a small case with interior masks and a gap.
- **The fallback.** Version 4's computation is used, and the record says so, when:
  - fewer than 200 pairs at lag 1 or at lag 2;
  - a non-finite moment;
  - `γ1 ≤ 0` or `γ2 ≤ 0`;
  - `φ` outside (0, 0.99);
  - `σ_w² ≤ 0.01 γ0`;
  - a whitened design whose condition number passes `1e8`.
- **Stated limits.** The plug-in covariance's uncertainty and the selection of extra frequencies
  are not propagated. B1.3 measures their effect, and `beta` is not applied on top of the GLS
  error. This is not stage A's oracle, which fits jointly with a box column. The flag, and the
  FAIL and INCONCLUSIVE rule, are unchanged.

### E4. The background: a local quadratic baseline per window (`battery_v51_diff.a0_depth` for the `sap_bkg` series only)

The background series is already detrended by version 4's mask-aware additive detrender: a robust
local quadratic over a 1-day window, `df.AdditiveDetrender`. Stage A (c1) found A0's error still a
median 23 times the white box error. The background's out-of-transit variability is a median 65
times its point-to-point scatter. That ratio was measured on the original background, so it does
not show by itself the timescale of what is left after the 1-day detrending (Codex's round 3).
Whether the quadratic operator lowers A0's error is therefore a question that the measurement
answers, not an assumption.

**The change.** Version 5 changes only the box operator. For the real events and for every
pseudo-window of the comb, identically, the baseline is a quadratic in time fitted by least
squares to the window's own two baseline bands. The in-event box depth is that quadratic's mean at
the in-event cadences, minus their mean flux.

- Version 4 used the bands' mean.
- The operator is local to each window, so no global model is fitted and none needs refitting per
  comb. The mask-aware preprocessing stays version 4's, so the measurement and its A0 error stay
  one family.
- **The solution (frozen).** Least squares by QR, on time centred at the window's centre and scaled
  by its half-width.
- **The fallback, the same geometric rule for real events and pseudo-windows:** fewer than 3
  baseline cadences on either side, or a scaled design whose condition number passes `1e6`. Such a
  window uses version 4's operator, and the record says so.
- **Its own white error.** The quadratic's prediction adds uncertainty to the band mean. Any white
  error reported for E4 is the new operator's own, `σ sqrt(Σ c_k²)` from its weights `c_k`, not the
  band mean's.

**The protected alternative and its preservation (Codex's round 2).** Version 4's background block
simulates the alternative as `frac_alt * sap_depth` directly: a rise confined to the in-event
span, to which the box responds fully. Version 5 keeps that **same alternative profile**, a rise
confined to the in-event span, with the same amplitude.

- The quadratic is fitted on the bands only, so under that profile its response is exactly 1, and
  the block's simulation stays valid with no response factor. The real events stay masked in the
  mask-aware detrender, as in version 4.
- A synthetic test checks that response as the difference between the measurement with the
  injection and without it, on a slowly varying background. The confined rise must come out within
  1 % of its injected amplitude, also through the fallback operator, or the test fails and blocks
  E4 (Codex's round 3).
- Broader profiles (rises over 1.5 and 2 durations, into the bands) are not in the protected
  alternative of either version. The test reports both operators' responses to them, as
  information.

The SAP depth `g_sap` and the rule are unchanged. The flux path is unchanged: `aperture_depth`,
the SAP sub-check and `odd_even` keep version 4's operator.

### What version 5 does not change

Version 5 leaves alone:

- the candidate generation, the gate and the plan;
- the aggregation;
- the sector selector and its refusals;
- `nearby_contamination`, `period_alias`, and `aperture_depth`'s own statistic, except for E1's
  completion where A0 refuses.

The blockers outside these estimators stay, and B1 reports them as they are.

## 3. The steps

### B1.1, implementation and tests

`battery_b1.py`, its synthetic tests, and a smoke on one D2 planet and one T2a injection, charged
to `b1_smoke`. Codex reviews the code against this design before any B1.2 run.

### B1.2, screening (diagnostic, D2 only)

It runs version 5 on the 31 recorded D2 losses, and on the 81 planets that version 4 kept, rebuilt
as stage A (b) did from C1's seeds 1000 to 1119. For each test it reports every status transition,
from version 4 to version 5:

- PASS to INCONCLUSIVE or FAIL, and the reverse;
- changes in the sensitivity blocks;
- the error ratios against stage A's bounds;
- the branches used.

It chooses nothing. A correction it motivates is a prospective amendment, recorded, and it is then
evaluated on new data. **T2a's population is not screened**: B1.4 measures it as a census, and
screening part of it would leak.

### B1.3, recalibration (development; independent contrasts)

**E1, E2 and E3** run on **450** new C1 planets, family P, seeds `c1.development_seed("P", i)` for
i from 4000 to 4449.

- **One contrast per curve.** Each curve gives one null contrast per estimator, so the contrasts
  are independent.
- **The pseudo-ephemeris.** The real transits and their bands stay masked. The pseudo-ephemeris is
  the candidate's, shifted by a quarter period, and is refused if any of its windows overlaps a
  true transit's window or bands.
- **E1's contrast.** The odd-even difference at the pseudo-ephemeris, with version 4's weights and
  E1's variance. It is taken only on the curves where version 4's `group_variance` refuses. If
  fewer than 30 curves give one, E1's criteria are UNRESOLVED by size.
- **E2's contrast.** The same difference, by E2's GLS where its conditions hold. Its expectation is
  0.
- **E3's contrast.** The residual box at the pseudo-ephemeris, after the masked GLS fit, with the
  same frequency selection.

**E4** runs on **real** background series, because C1's auxiliary background is constant with
white noise and cannot test slow variability.

- **The hosts.** The original curves of the 16 C2 hosts that passed the v0.4 gate. They are outside
  T2a's population (the 84 hosts that did not pass), so the census does not see them.
- **The pseudo-ephemerides.** Each host gets up to 8, from a frozen draw (seed
  `refute-v053-b1:e4-null`): period uniform in [1, 15] d, duration uniform in [1.5, 6] h, phase
  uniform. A pseudo-ephemeris is kept only if none of its windows overlaps a window of the host's
  catalogued candidates or of the pseudo-ephemerides already kept.
- **Inference by host.** The contrasts of one host share its preprocessing, error estimates,
  variability and instrument, so they are not independent. The unit of inference is the host: a
  host-cluster bootstrap with 2,000 replicates and seed 20261113, percentile intervals.
- **Transport.** These hosts passed the gate and T2a's did not, so carrying their result over to
  T2a's hosts is not shown. It is stated as a limit.

**The criteria and their intervals (frozen).** Each criterion uses the z-score
`z = statistic / error`. Every interval is two-sided at 95 %, simultaneous over the 12 criteria
(Bonferroni, each at `1 - 0.05 / 12`).

| Criterion | Tolerance | Interval (E1 to E3) |
|---|---|---|
| the mean of `z` | within ±0.15 | Student t |
| its standard deviation | within [0.85, 1.15] | chi-square |
| the fraction with `|z| > 3` | at most 0.015 | Clopper-Pearson |

E4's intervals come from the host-cluster bootstrap. At 450 contrasts, zero excesses beyond 3 give
a Clopper-Pearson upper end below 0.015, so a PASS is possible. 409 is the minimum for that.

**The outcomes.** Each criterion's result is one of three:

- **PASS:** the interval lies inside the tolerance.
- **FAIL:** the interval lies wholly outside the tolerance. That is a mean outside ±0.15 on either
  side, a standard deviation above 1.15, or a fraction beyond 3 above 0.015.
- **UNRESOLVED:** otherwise.

A standard deviation whose interval lies wholly below 0.85 (conservative) is reported, and it is
not a FAIL.

**What the intervals mean (Codex's round 3).** Independence between curves does not make the
pulls normal. Estimated errors, branch selection and mixed regimes can make them otherwise, and
the chi-square interval for a standard deviation depends on normality. The t, chi-square and
Clopper-Pearson intervals are therefore **diagnostics conditional on that model**. B1.3 claims no
demonstrated simultaneous coverage. A PASS is a diagnostic statement, not a calibration. A FAIL is
an **exploratory conservative veto**: it excludes the estimator from the forecast, and it is
presented as such. The absence of a veto is never read as calibration.

**Availability, by the population each new branch applies to.** For E1, that population is version
4's relevant refusals. For E2 to E4, it is every curve or pseudo-ephemeris given to them. The
record keeps, separately:

- the attempts;
- the eligible cases;
- the new-path runs;
- the fallbacks;
- the contrasts available.

If fewer than 80 % of the eligible cases give a contrast, or fewer than 30 contrasts exist, the
estimator cannot PASS. **A FAIL obtained on at least 30 contrasts stands.**

**E4's host bootstrap (Codex's round 3).**

- Each host carries equal weight.
- At most 8 pseudo-ephemeris proposals are drawn per host, with no redraws.
- A degenerate bootstrap (every replicate equal) gives UNRESOLVED for that criterion, never a
  PASS. So does a tail fraction with no excess beyond 3, or with too little support (fewer than
  100 contrasts).
- The 16 hosts' intervals are exploratory, and dependence between hosts through the instrument is
  not excluded.
- The composition that follows is a development decision, with no calibrated permission for T2a.

**The consequence, and the composition frozen before the forecast.** A deterministic rule computes
the composition from B1.3's results, and it is recorded before B1.4 runs.

- An estimator with any FAIL is **not used**, and version 4's computation stays for it.
- If E1 is not used, E2 runs only where its own conditions hold, and otherwise exactly as version 4.
- If E2 is not used, `odd_even` is version 4's, with E1 if E1 is used.

UNRESOLVED is the expected result at this size. B1.3 is then a screen for gross deviations, not a
calibration. The absence of a FAIL shows neither calibration nor conservatism. The acceptance does
that.

### B1.4, the forecast (development)

**D2 and D4.**

- **The curves.** 200 new C1 planets: family P, seeds `c1.development_seed("P", i)` for i from
  3000 to 3199.
- **The batteries.** v0.4, version 4 and version 5 attack the same candidate, as
  `forecast_v4.one` does.
- **The rules.** The frozen rules, through `c1.decision_rules`, with their eligibility floor (at
  least 20 eligible) and v0.4 as the comparator on the same curves:
  - **D2:** kept over eligible at least v0.4's minus 0.10, and REFUTED at most 0.05 with its Wilson
    95 % upper end at most 0.10;
  - **D4:** INCONCLUSIVE at target SNR 15 or more, at most 0.30.
- **The report.** The rule's own result is the forecast. A conservative diagnostic, the Wilson
  interval of kept and of D4's fraction, is reported apart and adds no condition.
- **The seeds.** Before any run, the seeds are checked against every development seed and index
  recorded in v0.5.1, v0.5.2 and stage A, smokes included.

**T2a, a census.** The design rests on two facts from Codex's round 1:

- with 80 and 80 injections, configuration B cannot reach PASS even if all 160 are kept, since the
  lower end is 0.865;
- a new sample that excluded v0.5.2's 110 injections would come from different populations.

B1 therefore measures **every injection of the strata with 2 to 4 sectors and 5 to 20 sectors**
(302 + 257 = 559), v0.5.2's 80 included, with version 5. Their T2a outcomes then carry no
sampling uncertainty.

- **The estimand and minimum** are v0.5.2's: 615 injections in 84 hosts, at least 551.5 kept.
- **Each injection** is rebuilt by `c2.tasks_for`. v0.4's battery must first reproduce the
  injection's v0.4 record (`c2.compat_problems`); a mismatch makes the injection unknown. Version 5
  then runs as built (A) and with the selector treated as certified and the refusal lifted (C).
  B follows by v0.5.2's rule:
  - B equals C at 20 sectors or fewer;
  - B equals A above 20.
- **Unknowns** count as lost for the lower end and as kept for the upper end.
- **Above 20 sectors.** A and B lose these injections by the refusal rule. C is measured on the 56
  only if a smoke (one injection of the most sectors, v0.4 and version 5 C) takes at most 20
  minutes of wall time.
  - **An overrun is a stop.** The driver's limit per shard is 1,700 s, and its rule is kept: a shard
    that passes the limit stops the run (`driver.py`). The stop and its state are brought to the
    maintainer, and the injections not run stay unknown.
  - If the smoke takes longer than 20 minutes, C above 20 is not run. It stays unknown, and the
    stop prices it.
- **The explicit answer, from configuration B** (Codex's round 2). Let `K_B` be the injections B
  keeps among the 559, and `U_B` the unknown ones. The 56 above 20 are lost in B.
  - **Yes, the margin exists without certifying above 20 sectors:** `K_B ≥ 552`.
  - **No:** `K_B + U_B ≤ 551`.
  - **Unresolved:** otherwise.

  B assumes the selector certified **up to** 20 sectors. That certification is itself owed
  (v0.5.2's design, section 2), and the stop prices it. A favourable B does not approve A.
- **If the answer is not yes,** C is the counterfactual of a selector also certified above 20, and
  the stop brings that certification's design and price. The design is v0.5.2's selector
  evaluation, extended with constructions of 25, 30, 40 and 60 sectors; the price comes from the
  measured cost per injection.
  - Let `K_C` and `U_C` be C's kept and unknown injections among all 615, the 56 above 20 included.
    Those 56 are unknown when C is not run above 20.
  - **Certification above 20 cannot rescue T2a** only if `K_C + U_C ≤ 551`. When C above 20 is not
    run, that reduces to `K_C + U_C (559) + 56 ≤ 551`.
  - A shortfall of B alone does not show that, since C can keep injections above 20.
- **Downloads.** The hosts are fetched by B1's own fetch, which reuses v0.5.2's logic with B1's own
  host list and destination (`.cache/v053/stageB/t2a-cache`, re-using the files already in
  `.cache/v052/s2/t2a-cache` by hash). Each file must match its sealed URL and SHA-256. The
  transient rule applies: 5 attempts, 120 s. URLs, sizes, hashes and times are recorded.

## 4. Caps and running

**CPU.** [`ledger_b.py`](../validation/v0.5.3/stageB/ledger_b.py) moves B1's 120 CPU-h from
`b1_unallocated` before each part runs. Each run, before it starts, checks:

- the part's strict cap: 1.5 times its allocation less its earlier attempts, over the 10 %
  overshoot;
- stage B's global cap, with one batch's in-flight reserve;
- `refuse_new_identity`;
- the ledger's lock, held for the whole run.

The costs in the table are estimates, to be confirmed by B1.1's smoke, and priced from what
actually runs: v0.4, version 4 and version 5 (A and C).

- The T2a census runs as two parts, `b1_t2a_2to4` (20 CPU-h) and `b1_t2a_5to20` (18), plus
  `b1_t2a_above20` (22) if the smoke allows it: 60 in all, allocated before their dispatch. Each
  projects its own cost from its driver checkpoint, and each stops at its strict cap.
- All accounting goes through the ledger.

| Part | CPU-h | Basis |
|---|---|---|
