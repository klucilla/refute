## Findings

### F-1. Version 3's output depends on the process's state

Recorded by the maintainer's decision received on 2026-11-24 at 22:38 local (#218, comment
7149778857), item 3. It was not investigated in this phase.
- **Where.** CI run 45514526728 (commit `84010d0`, whose `src/` is `eb70c13`'s), test
  `tests/test_v0511_identity.py::test_versions_1_to_4_give_the_baseline_bytes`, on both "rest"
  shards (ubuntu-24.04 with Python 3.12, and windows-2025 with Python 3.13).
- **What.** `verdict-v3.txt` differed in the last digits of some floats, for example
  `amplitude_snr`, between two computations with the same code:
  - one in the pytest process, after thousands of other tests;
  - one in a fresh subprocess.

  Every other output was equal, and 3981 other tests passed.
- **What was done.** `64f3331` computes both sides in fresh subprocesses, so the identity test
  compares code against code.
- **Why it matters.** The dependence on the process's state is a risk for byte-for-byte
  reproducibility. Its cause must be identified before any lock. It is carried to the v0.5.12
  proposal ([../plans/v0.5.12-proposal.md](../plans/v0.5.12-proposal.md)).
