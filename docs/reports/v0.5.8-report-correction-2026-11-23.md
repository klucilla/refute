## 1. Door 1, read as in the public note

**The report says** (section "The four doors", "What the doors say, read plainly"): "About one
decided output in seven changed class when only the seed changed."

**It is read as:** about one decided output in seven changed class in the TOI-seeded rerun (15 of
107, including two runs that ended in ERROR).
- **The two ERRORs** are TOI-734.01 (an `OverflowError` after the fit) and TOI-531.01 (a
  600-second timeout before the fit).
- **The modes.** The rerun compares v0.5.6's search mode with the TOI-seeded mode.
- **The files.** File identity was verified for 83 of 167 records. Over those (the `same` panel),
  10 of 54 decided outputs changed.

**The same caveat** applies to "under one change of seed" in the section "What this phase does not
do". The numbers describe how these 167 outputs moved between v0.5.6's search mode and the
TOI-seeded rerun:
- file identity was verified for 83 records only;
- 5 runs ended in ERROR, three of them (two failed downloads and a timeout) before the fit.

The report's numbers are unchanged. The `same` panel (10 of 54) is already in the report's door
table and in [`stability-report.md`](../validation/v0.5.8/stability-report.md).
