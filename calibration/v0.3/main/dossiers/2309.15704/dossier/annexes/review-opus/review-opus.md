## Summary (two sentences)
All three drawn claims (Table 2, Interpolation block: energy/Ensemble AN 98.7, wine/Bayesian Ensemble BN 33.9, naval/Bayesian Ensemble BN 46.9) are `INCONCLUSIVE`. In each claim the base run exited with code 1 after 11 s because the artifact's `run.py` ignores the long option `--config`, and the profile follows the rules in docs/verdicts.md as they are written. The dossier is intact and the transcription matches the paper, but the claims were locked with a coverage route that is declared to find nothing, and the run's failure has a deterministic cause that the dossier records as "undetermined".

## Checks with no objection
- **Integrity.** `refute.exe check-dossier` printed "core: intact against its seal" and "OK: manifest intact", exit 0. SEAL.json lists the same 15 files as MANIFEST.sha256 plus the manifest itself, with matching hashes. `claim_file.json`, `claim_input.json`, `dossier.json` claim_file_sha256 and `profiles/{build,run}.json` claim_sha256 all equal 598543…4957. The log hashes in provenance.logs equal the manifest. The `requirements.lock` and `pyvenv.cfg` hashes equal provenance.environment.
- **Transcription against the paper.** In arXiv 2309.15704v2, Table 2 ("UCI experiments OOD detection results. AUROC scores", page 21 of the PDF; the values were read from the arXiv HTML version), the Interpolation block has energy / Ensemble AN = 98.7, wine / Bayesian Ensemble BN = 33.9 and naval / Bayesian Ensemble BN = 46.9. All three match targets[*].metric.reported and source.location. The metric is AUROC in %, from one run per value ("Each experiment is performed only once"), which matches reported_n_seeds 1 and uncertainty none.
- **Mapping to code.**
  - Ensemble AN is `AnchoredNetwork` with the top-level n_estimators 5. Bayesian Ensemble BN is `BNN5` (uci_all.yml lines 47-67 and 115-123).
  - The paper's 10k and 50k iterations equal epochs × steps_per_epoch (100×100 and 500×100).
  - Selection by validation NLL ("selected based on hold-out validation NLL") matches train.py lines 254-262.
  - Extraction file `logs/results/uci/<dataset>_<method>_0.csv`, row `auc_ood`, unit fraction: this follows run.py 159-160, train.py 288-291 and utils.py 233.
  - metric_recompute is not applicable, correctly: per-example sigmas are not saved (utils.py 227-235).
- **Derived splits.** uci_interpol (datasets.py 216-223) with sklearn train_size 0.9 gives:
  - energy: 192+192 in-distribution, test 39, plus 384 OOD = 423;
  - wine: test 80 + OOD 800 = 880;
  - naval: test 597 + OOD 5967 = 6564.
  These equal expected_examples.
- **Data.** The URLs and file names in test_plan.datasets match uci_datasets.py lines 14-33 at c67aa62 (naval from the trewaite copy at 15bb3ed). `data_present` passed with 768, 1599 and 11934 rows.
- **Build.** The `requirements_compiled` rung completed with Python 3.11 (the README prefers 3.11) and exclude-newer 2025-02-12: 67 packages, including tensorflow 2.12.0 (logs/setup_build_requirements_compiled.log lines 16-206 and 253-320). The other rungs were correctly not applicable.
- **Verdict rules.**
  - Rule 1 (a base gate that did not pass) applies. `run_completed` is never attributed to the documented command (docs/verdicts.md 81-105), so each claim is `INCONCLUSIVE`, with no attack run.
  - The profile headline "3 of 3 drawn claims: INCONCLUSIVE" and `has_negative: false` follow docs/verdicts.md 126-138, so there is no right-of-reply trigger.
- **Text.** The dossier messages describe no reproduction as obtained (`basic_reproduction_obtained: false`), do not present the inconclusive result as positive, and say nothing about the authors.
